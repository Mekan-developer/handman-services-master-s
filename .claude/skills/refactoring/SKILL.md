# Refactoring

Аудит и чистка всего проекта. Три задачи, у каждой своё правило:

| Задача | Что делаем |
|---|---|
| Неиспользуемые файлы и папки | Удаляем, но только с доказательствами и обратимо (git) |
| Уязвимости в коде | Только сообщаем. Ничего не правим без согласия пользователя |
| Нарушения архитектуры | Только сообщаем |

Общаемся с пользователем на русском.

## Аргументы

- `/refactoring` — полный прогон (все три задачи)
- `/refactoring unused` — только неиспользуемые файлы
- `/refactoring security` — только уязвимости
- `/refactoring dry-run` — ничего не удалять, только показать список кандидатов и находки

## Главные правила

1. **Удаление на основе одного сигнала запрещено.** Файл считается неиспользуемым, только если нет ссылок на него ни в коде, ни в конфигах, ни по конвенции фреймворка (см. фазу 2).
2. **Всё обратимо.** Работаем в отдельной git-ветке, удаляем через `git rm`, коммиты делаем по категориям. Никаких `rm -rf` по неотслеживаемым файлам без отдельного подтверждения.
3. **Поведение не меняется.** Это чистка, а не переписывание. Код не правим, кроме удаления мёртвых файлов.
4. **Уязвимости не чиним молча.** Находим, описываем, предлагаем фикс, ждём ответа.
5. **Секреты в отчёте маскируем** (`sk_live_****abcd`), полное значение нигде не выводим.
6. **Сомневаешься — не удаляй**, а перенеси в список «спросить пользователя».

## Фаза 0. Подготовка

1. Определи стек по файлам: `composer.json` (Laravel), `package.json`, `nuxt.config.*` (Nuxt 3), `vite.config.*` (Vue/Inertia), `pubspec.yaml` (Flutter), `docker-compose*.yml`.
2. `git status`. Если есть незакоммиченные изменения — остановись и скажи об этом пользователю. Не начинай чистку по грязному дереву.
3. Если репозитория нет — скажи об этом и не удаляй ничего (откатить будет нечем). Предложи `git init` и первый коммит либо архив проекта.
4. Создай ветку `refactor/cleanup-YYYYMMDD`.
5. Сними baseline: тесты (`php artisan test` / `./vendor/bin/pest`), сборка (`npm run build`), `flutter analyze` — что применимо. Запиши, что падало **до** твоих изменений, чтобы потом не путать.

## Фаза 1. Инвентаризация

Составь дерево проекта, исключая: `.git`, `vendor`, `node_modules`, `storage` (кроме проверки лишних файлов), `bootstrap/cache`, `public/build`, `.nuxt`, `.output`, `dist`, `build`, `.dart_tool`.

Выпиши кандидатов по категориям из фазы 2. Не удаляй ничего на этом шаге.

## Фаза 2. Неиспользуемые файлы и папки

Для каждого кандидата проверь минимум два независимых сигнала:
- поиск по имени файла без расширения;
- поиск по FQCN / импорту / строковому имени (`'Admin/Users/Index'`, `'orders.show'`);
- поиск в конфигах: `composer.json`, `package.json` (scripts), `vite.config`, `nuxt.config`, `docker-compose`, nginx/supervisor, CI (`.github`, `.gitlab-ci.yml`), `pubspec.yaml`, `routes/*`, `config/*`, `bootstrap/*`.

### Что искать

**Явный мусор:** `*.bak`, `*.orig`, `*.old`, `*.tmp`, `*copy*`, `*(1)*`, дампы БД в корне, закоммиченные `*.log`, `.DS_Store`, `Thumbs.db`, пустые папки, закомментированные целиком файлы, дубликаты (`Component.vue` и `Component_new.vue`).

**Laravel:**
- контроллеры без маршрута; Form Request, Service, Repository, Resource, Enum, Job, Mail, Notification, которые нигде не упоминаются;
- Blade-вью: ищи `view('...')`, `@include`, `@extends`, `<x-...>`, `Inertia::render('...')`, письма;
- модели без упоминаний (но проверь morph map, связи, `$with`, фабрики и сидеры);
- seeders — проверь `DatabaseSeeder`; factories — проверь тесты и сидеры;
- lang-файлы и ключи, на которые нет ссылок (`__()`, `trans()`, `@lang`) — только отчёт, не удалять.

**Vue 3 / Inertia:**
- страницы: сверяй с `Inertia::render('Path/Name')`; учти, что страницы могут подтягиваться через `import.meta.glob` — тогда они «используются» по конвенции;
- компоненты, composables, stores, ассеты, на которые нет `import` и нет auto-import (`unplugin-vue-components`, `unplugin-auto-import`).

**Nuxt 3:** `components/`, `composables/`, `utils/` подключаются автоматически, `pages/` — маршруты по файлам, `layouts/`, `middleware/`, `server/api/`, `plugins/` тоже по конвенции. Проверяй использование по имени компонента (`<UserCard>`, `<LazyUserCard>`), `definePageMeta`, `useXxx()`.

**Flutter:** `.dart` файлы без импорта; ассеты, которых нет в `pubspec.yaml` или на которые нет ссылок; неиспользуемые пакеты в `pubspec.yaml` (только отчёт). Сгенерированные файлы (`*.g.dart`, `*.freezed.dart`) не трогай.

**Node.js (`socket-server/` и подобные сервисы):** точка входа берётся из `main`/`scripts` в его `package.json` и из `Dockerfile`/`docker-compose`; модули без `require`/`import` от точки входа — кандидаты. Неиспользуемые зависимости — только отчёт.

**Broadcasting / события:** события и каналы (`ShouldBroadcast`, `routes/channels.php`) могут слушаться только внешними клиентами (Flutter, socket-server) — отсутствие ссылок в PHP/Vue не доказывает, что они не нужны. Максимум уровень B.

**Документация и API-коллекции (`docs/`, `bruno/`):** не код, но используются людьми и мобильными командами. Максимум уровень B.

### Уровни уверенности

- **A — удаляем:** ноль ссылок во всём репозитории, включая конфиги, и файл не подключается по конвенции фреймворка.
- **B — спрашиваем:** ссылки возможны через динамику (строки, `glob`, переменные в `view($name)`, рефлексия, morph map), либо файл выглядит как заготовка на будущее.
- **C — оставляем.**

### Никогда не удалять

`.env*`, `.git*`, lock-файлы, `.gitkeep`, **миграции** (даже «старые»), `vendor`, `node_modules`, `README*`, `LICENSE`, Docker/CI/nginx/supervisor конфиги, `composer.json`, `package.json`, `pubspec.yaml`, `bootstrap/providers.php`, `bootstrap/app.php`, `storage/*/.gitignore`, сгенерированные файлы, всё в `public/`, на что ссылаются шаблоны или внешние системы (favicon, robots.txt, sitemap, manifest).

Дополнительно для этого проекта: `CLAUDE.md`, `AGENTS.md`, `boost.json`, `.mcp.json`, всё в `.claude/`, `phpunit.xml`, `phpstan.neon`, `public/maps/` (тайлы, шрифты, стили карт).

### Порядок удаления

1. Удаляй только уровень A.
2. Один коммит на категорию (мусор, Laravel, фронтенд, Flutter и т.д.): `git rm`, сообщение `chore: remove unused <категория>`.
3. После каждой категории — тесты и сборка. Если что-то упало, чего не было в baseline: `git revert` этой категории, перенеси файлы в список B и скажи об этом.
4. Пустые папки после удаления тоже убери.

## Фаза 3. Уязвимости (только отчёт)

Читай код, а не только grep: вредный паттерн опасен, только когда в него попадает пользовательский ввод.

### Laravel / PHP
- **Mass assignment:** `$guarded = []`, `$request->all()` в `create`/`update`/`fill`.
- **SQL-инъекции:** `DB::raw`, `whereRaw`, `orderByRaw`, `selectRaw`, конкатенация строк в запросах с вводом пользователя; динамические имена колонок для сортировки без белого списка.
- **Авторизация и IDOR:** `Model::find($id)` / route binding без проверки владельца; контроллеры без Policy/Gate; админ-маршруты без middleware.
- **XSS:** `{!! !!}` в Blade, `v-html` во Vue с данными пользователя.
- **Загрузка файлов:** нет валидации mime/размера, оригинальное имя файла, сохранение исполняемых файлов в `public`.
- **Инъекции команд и SSRF:** `exec`, `shell_exec`, `system`, `Process` с вводом; `Http::get($userUrl)`, `file_get_contents($userUrl)`; `unserialize` с внешними данными; open redirect (`redirect($request->input('url'))`).
- **Аутентификация:** нет rate limiting на логин, OTP, сброс пароля, платёжные эндпоинты; слабая валидация паролей; токены Sanctum без срока и scopes.
- **Платежи и вебхуки:** вебхук (эквайринг, CloudPayments) без проверки подписи; сумма и статус берутся от клиента, а не с сервера; нет идемпотентности; повторная обработка одного платежа.
- **Конфигурация:** `APP_DEBUG=true` для прода, открытые `/telescope`, `/horizon`, `phpinfo`, debug-маршруты; `CORS *` вместе с credentials; небезопасные настройки cookie/session; `.env` или ключи в репозитории и в git-истории.
- **Прочее:** логирование паролей, токенов и карточных данных; хранение секретов в коде.
- `composer audit` и `npm audit` — запусти и приведи результат.

### Vue / Nuxt
- секреты в `runtimeConfig.public`, ключи и токены в клиентском коде и `.env` с префиксом `VITE_`/`NUXT_PUBLIC_`;
- `v-html`, `innerHTML`, `eval`, `new Function`;
- токены в `localStorage` без необходимости; отсутствие проверки ролей на серверных маршрутах (`server/api`), а не только на клиенте.

### Flutter
- токены и данные пользователя в `SharedPreferences` вместо `flutter_secure_storage`;
- захардкоженные ключи и пароли; `http://` вместо `https://`;
- отключённая проверка сертификатов (`badCertificateCallback => true`);
- логирование токенов и персональных данных в продакшене.

### Broadcasting / Realtime
- приватные и presence-каналы в `routes/channels.php`: callback реально проверяет, что пользователь — владелец/участник ресурса (IDOR через подписку на чужой канал);
- данные в `broadcastWith()`: не уходят ли лишние персональные данные (телефоны, координаты, токены);
- приём данных от клиента (геолокация, статусы) — валидация и rate limiting.

### Node.js / Socket.IO (`socket-server/`)
- аутентификация подключения (handshake): общий секрет/токен проверяется, сравнение в постоянном времени, секрет не захардкожен;
- `cors.origin: '*'` у Socket.IO/Express; открытые HTTP-эндпоинты моста без авторизации;
- валидация входящих событий и payload, лимиты размера (`maxHttpBufferSize`), rate limiting;
- логирование OTP-кодов, телефонов и токенов;
- `npm audit` в папке сервиса.

### Bruno / Docker / документация
- реальные токены, пароли, ключи в `bruno/environments/*.bru`, `docker/*.env`, `docker-compose*.yml`, `docs/`;
- открытые наружу порты БД/Redis в `docker-compose*.yml`, дефолтные пароли.

### Как сообщать
- **Critical и High — сообщай сразу, в момент находки,** не дожидаясь конца работы. Остановись и коротко покажи находку.
- Остальное — в итоговый отчёт.
- Для каждой находки: уровень (Critical / High / Medium / Low), `путь/файл:строка`, что не так, как это можно использовать (одно предложение), предложение фикса.
- Не исправляй. Спроси: «Исправить эти пункты?» и жди ответа.
- Если не уверен, что находка реальна, пометь «возможно» и объясни, чего не хватает для уверенности.

## Фаза 4. Архитектура (только отчёт)

Проект следует схеме Route → Controller → Service → Repository. Найди и перечисли отклонения:
- «толстые» контроллеры: бизнес-логика, запросы к БД, `DB::` и Eloquent прямо в контроллере;
- валидация в контроллере вместо Form Request;
- Service, обращающиеся к Eloquent напрямую в обход Repository (если Repository в проекте принят);
- N+1 (обращения к связям в цикле без `with()`);
- Repository с бизнес-логикой;
- места без тестов у ключевых сервисов.

Правок не делай, только список с `файл:строка`.

## Фаза 5. Итог

Заверши коротким отчётом на русском:

1. **Удалено** — сколько файлов и папок, по категориям (полный список — в коммитах).
2. **Нужно твоё решение (уровень B)** — список с причиной сомнения по каждому.
3. **Уязвимости** — таблица по уровням, количество и самые важные.
4. **Архитектура** — главные отклонения.
5. **Проверка** — тесты и сборка: до и после.
6. **Как откатить** — имя ветки и команда `git revert`/`git checkout`.

Полный отчёт сохрани в `.claude/reports/refactoring-YYYYMMDD.md` и добавь эту папку в `.git/info/exclude`, чтобы отчёт с уязвимостями не попал в репозиторий. Отчёт тоже маскирует секреты.
